> 本文档用于将项目交接给任意开发工具或开发者。它包含需求基线、现有实现、数据契约、模块边界、实施顺序、测试方式和验收标准。除非用户明确变更，本文规则优先于早期需求文档中未细化的表述。

## 1. 项目定位与最终目标

构建一个纯前端的智慧图书馆管理后台。系统服务于管理员，管理图书、读者和借阅记录；普通用户只能访问仪表盘与个人中心。没有真实后端，所有业务数据通过 Axios 自定义适配器模拟 `/api` 请求，并持久化在浏览器 `localStorage`。

技术栈固定如下：

- Vue 3 + Vite，JavaScript（不使用 TypeScript）
- Element Plus
- Pinia
- Vue Router 4
- Axios 自定义 adapter（禁止 mockjs）
- ECharts
- Vitest

启动命令：

```bash
npm install
npm run dev
```

质量门槛：每完成一个模块，先运行相关单元测试和 `npm run build`，向用户报告验收结果；**未得到用户允许，不得进入下一个模块**。

## 3. 不可违背的业务规则

### 3.1 角色和路由权限

| 角色 | 可见菜单 / 可访问路由 |
| --- | --- |
| `admin` | `/dashboard`、`/books`、`/users`、`/borrow`、`/profile` |
| `user` | `/dashboard`、`/profile` |

- 未登录访问任何受保护路由：跳转 `/login`。
- 已登录访问 `/login`：跳转 `/dashboard`。
- `user` 直接访问 `/books`、`/users`、`/borrow`：跳转 `/dashboard`，并用 `ElMessage` 提示“您无权限访问该页面”。
- 菜单隐藏不能代替路由守卫，二者必须同时实现。

### 3.2 借阅、库存与状态

- 新建借阅时，目标图书库存减 1。
- 还书时，目标图书库存加 1。
- 库存为 0 的图书不得出现在新建借阅图书下拉框中。
- 禁用读者不得出现在新建借阅读者下拉框中。
- 图书存在 `borrowing` 或 `overdue` 记录时禁止删除，并提示“该图书存在未归还的借阅，无法删除”。
- 库存必须是非负整数。
- 当前日期小于或等于应还日期、且未还书：`borrowing`。
- 当前日期超过应还日期、且未还书：`overdue`。
- 正常期限内归还：`returned`。
- 逾期后归还：`overdue_returned`，不能错误地改为 `returned`。
- 查询、仪表盘统计和还书前都应基于当前日期动态刷新未归还记录的 `borrowing/overdue` 状态。

### 3.3 读者、图书唯一性

- ISBN 唯一。
- 读者学号唯一。
- 读者手机号唯一。
- 新增读者时密码必填；编辑读者时密码留空代表不改密码。
- 可禁用拥有未归还图书的读者，但先确认并提示“该读者有未归还图书，禁用后将无法新增借阅”。
- 禁用后仍允许其归还已有借阅。

### 3.4 本地持久化

| Key | 用途 |
| --- | --- |
| `library_mock_data` | 图书、读者、借阅业务数据；唯一业务数据 Key |
| `library_auth_token` | 当前用户 Token |
| `library_user_info` | 当前用户资料 |

侧边栏的“重置演示数据”必须只调用 `resetLibraryData()`，恢复业务初始数据；不应强制退出当前用户。

## 4. 数据模型与 API 契约

后续代码必须优先通过 ID 关联，不能只依赖名称，避免编辑姓名或书名后关联失效。

```js
// Book
{
  id: Number,
  isbn: String,
  name: String,
  author: String,
  category: '文学' | '科技' | '历史' | '艺术' | '其他',
  stock: Number, // 非负整数
  description: String,
  cover: String,
  createdAt: 'YYYY-MM-DD'
}

// Reader
{
  id: Number,
  name: String,
  studentId: String,
  gender: '男' | '女',
  phone: String,
  password: String,
  registerTime: 'YYYY-MM-DD',
  status: 'normal' | 'disabled',
  avatar: String
}

// BorrowRecord
{
  id: Number,
  bookId: Number,
  bookName: String,     // 展示冗余字段；以 bookId 为准
  readerId: Number,
  readerName: String,   // 展示冗余字段；以 readerId 为准
  borrowDate: 'YYYY-MM-DD',
  dueDate: 'YYYY-MM-DD',
  returnDate: 'YYYY-MM-DD' | null,
  status: 'borrowing' | 'overdue' | 'returned' | 'overdue_returned'
}
```

建议完善 API 模块，让页面只使用 API，不直接操作 `localStorage`：

```js
// book.js
getBookList(params)
createBook(payload)
updateBook(id, payload)
deleteBook(id)

// user.js
getReaderList(params)
createReader(payload)
updateReader(id, payload)
toggleReaderStatus(id)

// borrow.js
getBorrowList(params)
createBorrow(payload)
returnBook(id)
```

所有成功响应保持：`{ code: 200, message: '操作成功', data }`。参数、校验或业务规则失败应通过 rejected Promise 抛出带中文说明的 `Error`，页面统一使用 `ElMessage.error(error.message)`。

## 5. 统一工程约定

1. 使用 Vue 3 Composition API 与 `<script setup>`。
2. 表格、表单、弹窗必须使用 Element Plus；不要重复造基础组件。
3. 业务模块中先调用 API，再由 API / adapter 更新 localStorage；不要在页面内复制存储逻辑。
4. 每一个新增业务函数先写失败测试，再写最小实现，再运行测试。禁止先实现后补测试。
5. 删除操作一律 `ElMessageBox.confirm`；成功/失败一律 `ElMessage`。
6. 表格请求过程中显示 `v-loading`；列表区支持横向滚动。
7. 视觉：背景 `#f0f2f5`，主色 `#409EFF`，白色卡片轻阴影，最小宽度 1200px。
8. 状态标签：借阅中蓝色、逾期红色、已归还绿色、逾期归还橙色。
9. 在每个模块结束前运行：

```bash
npm run test
npm run build
```

构建阶段可能出现 ECharts 体积大于 500kB 的警告；这是警告而非失败。仪表盘模块完成后可使用路由懒加载降低首屏包体。

### 模块 5：借阅记录与库存联动

**目标**：实现整个项目最关键的交易逻辑：新借阅、可选资源限制、状态计算、还书与库存反向更新。

**实现原则**：创建借阅与减少库存必须位于同一 adapter 操作中；还书与增加库存也必须位于同一操作中。先在内存中计算新数据，全部校验成功后一次 `saveLibraryData()`，避免半完成状态。

**实施步骤**：

1. 在 `borrowRules.js` 编写纯函数：`getDerivedBorrowStatus(record, today)`、`refreshBorrowStatuses(records, today)`、`isOutstanding(record)`。这里是测试优先的核心。
2. GET 借阅列表前刷新未归还状态；支持状态筛选和分页。
3. 在创建弹窗加载可借图书（`stock > 0`）和正常读者（`status === 'normal'`），支持 `filterable` 下拉搜索。
4. 借阅天数 `ElInputNumber`，默认 30、最小 1；使用本地日期函数精确计算应还日期，避免 `toISOString()` 造成时区偏差。

6. “还书”仅在未归还记录展示；确认后比较当天与 dueDate：逾期则 `overdue_returned`，否则 `returned`；写回 returnDate，库存 +1。
7. 详情可用只读 `ElDescriptions` 弹窗；非必需时不要扩大为新页面。
8. 页面标签颜色严格按统一约定。

**必须测试（高优先级）**：

- 日期晚于 dueDate 时为 `overdue`。
- 正常归还得到 `returned`；逾期归还得到 `overdue_returned`。
- 库存 1 的图书借阅一次后变 0，再次借阅失败。
- 借阅成功后记录新增且库存恰好减 1。
- 还书成功后库存恰好加 1；重复还书失败且库存不重复增加。
- 禁用读者与库存 0 图书无法创建借阅。
- 图书删除保护能识别动态转为 overdue 的未归还记录。
- 借阅记录刷新后状态与库存数据均持久化。

**验收结果**：展示一次借书、刷新后数据仍存在、还书后库存恢复的完整流程；等待用户许可。

### 模块 6：仪表盘与 ECharts

**目标**：从当前本地数据生成准确、响应式的统计、趋势、排行和最近借阅。

**新增/修改文件**：

```text
src/views/Dashboard.vue
src/components/StatCard.vue
src/components/BorrowTrendChart.vue
src/components/PopularBooksChart.vue
src/utils/dashboardMetrics.js
```

**统计口径（固定）**：

- 图书总数：`books.length`，即 ISBN/图书种类数，不是库存总册数。
- 读者总数：`users.length`，包含禁用读者。
- 借阅中：当前状态为 `borrowing` 或 `overdue` 的记录数。
- 本月新增图书：`createdAt` 属于当前年月的图书种类数。
- 近 7 天借阅趋势：以 `borrowDate` 分组；从今天向前连续七天，无记录日期填 0。
- 热门 TOP5：以所有借阅记录按 `bookId` 计数，降序；次数相同按书名升序，保证稳定。
- 最近借阅：以 `borrowDate` 倒序，再以 `id` 倒序取 5 条。

**实施步骤**：

1. 先为全部指标写纯函数测试，使用固定日期参数，禁止测试依赖真实当天。
2. `Dashboard.vue` 数据从 API 获取，加载中显示 `v-loading`。
3. 四卡一行，使用 Element Plus 栅格；图标可采用 Emoji 或 Element Plus 图标，但视觉需统一。
4. 创建两个独立图表组件，接收 plain props；组件 `onMounted` 初始化，`watch` 数据变化更新，`onBeforeUnmount` dispose；监听 resize。
5. 折线图用日期和借阅量；柱状图用书名与次数。无数据时显示空状态，不初始化异常图表。
6. 最近借阅表格使用实时推导后的状态标签。
7. 用路由懒加载载入仪表盘，减少初始 ECharts 包体。

**必须测试**：

- 固定日期下四项统计数字准确。
- 7 天连续日期与 0 值补齐准确。
- 并列热门书籍按书名排序。
- 最近记录限制 5 条且顺序正确。
- 状态刷新会影响“借阅中”统计。
- 图表组件在卸载时调用 dispose（可在测试中 spy ECharts 实例）。

**验收结果**：统计卡片、两张图和最近记录在页面可见，窗口变化不报错；等待用户许可。

## 8. 常见错误与规避方式

1. **只隐藏菜单，不拦截地址栏**：必须在路由守卫做角色判断。
2. **只保存书名/读者名**：必须保留 `bookId` 和 `readerId`，名称只是展示冗余。
3. **还书后一律写 returned**：必须依据当天是否超过 dueDate 写 `overdue_returned`。
4. **借阅与库存分开保存**：会产生库存与记录不一致；二者必须在同一 adapter 操作中一次提交。
5. **编辑读者空密码覆盖旧值**：空密码表示不更新该字段。
6. **仅在创建借阅时检查状态**：还要在 adapter 内二次校验库存和读者状态。
7. **把年月日转为 UTC ISO 字符串**：东八区可能日期偏移；使用本地年月日格式化函数。
8. **把页面状态当作真数据源**：localStorage 的 `library_mock_data` 才是单一业务数据源。
9. **重置时清空所有 localStorage**：会意外退出用户；只能重置业务 Key。
10. **ECharts 未 dispose 或不 resize**：会导致重复实例和布局异常。
